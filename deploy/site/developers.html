개발자 안내

OpenAI Chat Completions API와 같은 형식입니다. 기존 코드에서 주소와 키만 바꾸면 됩니다.

등급, 한도, 지원 값은 사용 안내에 있습니다.

끝점

기본 주소
https://ssalmuck-ai.duckdns.org/v1
모델
gemma-4-31b-it
요청내용
POST /v1/chat/completions대화의 답
GET /v1/models모델 목록
GET /v1/usage내 사용량과 한도
GET /v1/status서버 상태, 한도, 부른 쪽의 등급
GET /health서버가 응답하는지

입력은 32,768토큰, 출력은 8,192토큰까지입니다. max_tokens나 max_completion_tokens가 더 크면 8,192로 줄이고 x-sclmd-ignored에 적습니다. 요청 본문은 32MiB까지입니다.

인증

키는 두 머리글 중 하나로 보냅니다.

Authorization: Bearer <키>
x-api-key: <키>

키 없이 보낸 요청은 IP 주소별로 한도를 셉니다. 등록되지 않은 키는 401입니다. 아래 예제는 키를 환경 변수 SSALMUCK_API_KEY에서 읽습니다.

브라우저에서 다른 출처의 페이지가 부르면 키가 있는 요청에만 CORS를 허용합니다. 키 없는 요청은 브라우저가 막습니다.

curl

curl https://ssalmuck-ai.duckdns.org/v1/chat/completions \
  -H "Authorization: Bearer $SSALMUCK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gemma-4-31b-it",
       "messages": [{"role": "user", "content": "서울의 겨울을 두 문장으로 설명해 주세요."}],
       "max_tokens": 300}'

키 없이 쓰려면 Authorization 줄을 뺍니다.

Windows의 curl은 명령줄의 한글을 UTF-8로 보내지 않아 400이 날 수 있습니다. 이때는 요청을 UTF-8 파일로 저장해 -d @request.json으로 보냅니다.

파이썬

import os
from openai import OpenAI

client = OpenAI(base_url="https://ssalmuck-ai.duckdns.org/v1",
                api_key=os.environ["SSALMUCK_API_KEY"])

reply = client.chat.completions.create(
    model="gemma-4-31b-it",
    messages=[{"role": "user", "content": "파이썬으로 피보나치 수를 구하는 함수를 써 주세요."}],
    max_tokens=800,
)
print(reply.choices[0].message.content)

키 없이 쓰려면 api_key에 아무 값을 넣고 Authorization 머리글을 빈 값으로 덮어씁니다.

client = OpenAI(base_url="https://ssalmuck-ai.duckdns.org/v1",
                api_key="none",
                default_headers={"Authorization": ""})

자바스크립트

openai 패키지는 baseURL만 바꿉니다.

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://ssalmuck-ai.duckdns.org/v1",
  apiKey: process.env.SSALMUCK_API_KEY,
});
const reply = await client.chat.completions.create({
  model: "gemma-4-31b-it",
  messages: [{ role: "user", content: "자바스크립트의 Promise를 한 문단으로 설명해 주세요." }],
});
console.log(reply.choices[0].message.content);

스트림

"stream": true면 OpenAI와 같은 SSE로 답하고 data: [DONE]으로 끝납니다. "stream_options": {"include_usage": true}를 주면 [DONE] 바로 앞에 choices가 빈 조각 하나로 usage를 보냅니다.

stream = client.chat.completions.create(
    model="gemma-4-31b-it",
    messages=[{"role": "user", "content": "짧은 시를 한 편 써 주세요."}],
    stream=True,
    stream_options={"include_usage": True},
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
    if chunk.usage:
        print()
        print(chunk.usage)

첫 토큰이 나올 때까지 서버는 15초마다 : ping 줄을 보냅니다. 공식 라이브러리는 이 줄을 무시합니다. 직접 읽을 때는 :로 시작하는 줄을 건너뜁니다. 입력이 32,768토큰이면 첫 토큰까지 약 20초 걸립니다.

스트림이 아닌 요청은 답이 끝날 때까지 아무것도 오지 않습니다. 클라이언트의 시간 제한을 넉넉히 둡니다.

도구 호출

tools의 function, tool_choice의 auto와 none, role이 tool인 메시지를 받습니다. 호출은 message.tool_calls로 오고 finish_reason은 tool_calls입니다. 스트림에서는 호출 하나가 닫힐 때마다 delta.tool_calls 하나를 보냅니다.

tools = [{"type": "function", "function": {
    "name": "get_weather",
    "description": "도시의 지금 날씨",
    "parameters": {"type": "object",
                   "properties": {"city": {"type": "string"}},
                   "required": ["city"]}}}]

messages = [{"role": "user", "content": "서울 날씨 알려 줘"}]
reply = client.chat.completions.create(model="gemma-4-31b-it", messages=messages, tools=tools)
call = reply.choices[0].message.tool_calls[0]

messages += [reply.choices[0].message,
             {"role": "tool", "tool_call_id": call.id, "content": '{"temp_c": 3}'}]
reply = client.chat.completions.create(model="gemma-4-31b-it", messages=messages, tools=tools)
print(reply.choices[0].message.content)

tool_choice의 required나 특정 함수 지정은 강제하지 않고 x-sclmd-ignored에 적습니다. 함수를 지정하면 그 함수만 모델에 알립니다. "parallel_tool_calls": false면 첫 호출에서 답을 끝냅니다.

생각

기본은 생각 없이 답합니다. "reasoning_effort"에 none, minimal이 아닌 값을 주거나 "thinking": {"type": "enabled"}를 주면 생각한 뒤 답합니다.

생각은 message.reasoning_content로, 스트림에서는 delta.reasoning_content로 옵니다. 생각 토큰도 출력 토큰으로 셉니다. thinking.budget_tokens는 쓰지 않고 x-sclmd-ignored에 적습니다.

프롬프트 캐시

캐시는 사용자마다 따로이며 다른 사용자와 나누지 않습니다. 캐시된 입력은 한도에서 0.1배로 셉니다.

대화를 이어 가면 앞의 같은 부분은 다시 읽지 않습니다. 마지막 사용 후 15분 동안 유지합니다.

content part나 메시지에 "cache_control": {"type": "ephemeral"}를 붙이면 그 지점까지 저장합니다. "ttl"은 "15m"이 기본으로 RAM에, "1h"는 RAM과 암호화된 디스크에 둡니다. 표시는 요청당 4개까지입니다. 1,024토큰보다 짧은 앞부분은 저장하지 않고 x-sclmd-ignored에 적습니다.

reply = client.chat.completions.create(
    model="gemma-4-31b-it",
    messages=[
        {"role": "system", "content": [
            {"type": "text", "text": long_document,          # 1,024토큰 이상
             "cache_control": {"type": "ephemeral", "ttl": "1h"}},
        ]},
        {"role": "user", "content": "이 문서의 요점을 세 줄로 정리해 주세요."},
    ],
)
print(reply.usage.prompt_tokens_details)

usage.prompt_tokens_details.cached_tokens는 캐시에서 읽은 토큰, cache_write_tokens는 새로 저장한 토큰입니다. 31,000토큰 문서에서 첫 토큰까지 캐시 없이 22초, RAM 캐시로 0.2초, 디스크 캐시로 0.6초였습니다.

오류와 재시도

오류는 OpenAI와 같은 꼴의 JSON입니다.

{"error": {"message": "...", "type": "invalid_request_error",
           "param": null, "code": "context_length_exceeded"}}
상태code뜻
400context_length_exceeded입력이 32,768토큰보다 깁니다.
400-거절하는 값이 있습니다. message와 param이 그 값을 알려 줍니다.
401invalid_api_key등록되지 않은 키입니다.
413-요청 본문이 32MiB보다 큽니다.
429rate_limit_exceeded하루 한도를 넘었습니다. Retry-After가 몇 시간일 수 있습니다.
429concurrency_limit동시 요청이 너무 많습니다. 진행 중인 요청이 끝나면 다시 받습니다.
502-서버가 꺼져 있습니다. 본문은 비어 있습니다.
503-서버가 다시 시작하는 중입니다. Retry-After가 붙습니다.

파이썬 openai 라이브러리는 Retry-After가 120초 이하면 두 번까지 다시 시도하고, 그보다 길면 바로 RateLimitError를 냅니다. 직접 다시 시도할 때는 아래처럼 Retry-After만큼 기다리고, 하루 한도처럼 긴 대기는 포기합니다.

import time
from openai import RateLimitError, APIStatusError

def ask(messages, tries=5):
    for _ in range(tries):
        try:
            return client.chat.completions.create(model="gemma-4-31b-it", messages=messages)
        except (RateLimitError, APIStatusError) as e:
            if e.status_code not in (429, 502, 503):
                raise
            wait = float(e.response.headers.get("retry-after", "5"))
            if wait > 600:      # 하루 한도
                raise
            time.sleep(wait)
    raise RuntimeError("재시도 실패")

상태 JSON

GET /v1/status는 키 없이 부를 수 있습니다. 홈과 신뢰 페이지의 상태가 이 값입니다.

{"ok": true, "model": "gemma-4-31b-it", "version": "...", "uptime_s": 3725,
 "queue": {"under_way": 2, "waiting": 1},
 "live": {"tok_s": 41.3, "tok_s_1m": 37.8, "requests_1m": 9},
 "zdr": {...}, "limits": {...}, "caller": {"tier": "ip_unverified"}}
필드내용
ok요청을 받으면 true, 점검 중이면 false
model, version모델 이름과 서버의 판
uptime_s서버가 켜진 뒤 지난 초
queue.under_way
queue.waiting		처리 중인 요청과 기다리는 요청
live.tok_s지난 10초 동안 서버 전체가 낸 답 토큰의 초당 수
live.tok_s_1m지난 60초의 같은 값
live.requests_1m지난 60초 동안 끝난 요청 수
zdr기록과 캐시의 설정. 뜻은 신뢰 페이지에 있습니다.
limits등급별 tph·tpd, output_weight, cached_weight, concurrency
caller.tier부른 쪽의 등급: key, ip_verified, ip_unverified

서버가 막 켜졌을 때는 live가 null입니다.
