요청 경로

  1. 이용자에서 엣지까지는 HTTPS입니다. 엣지는 운영자 집의 Caddy 서버로, TLS를 풀고 요청을 GPU PC로 넘깁니다.
  2. 엣지에서 GPU PC까지는 집 안 LAN의 암호화하지 않은 HTTP입니다. GPU PC의 방화벽은 이 포트에서 엣지의 연결만 받습니다.
  3. GPU PC는 요청을 RAM과 GPU 메모리에서 처리합니다. 이용자가 보낸 X-Forwarded-For는 엣지가 버립니다.

남기지 않는 것

  • 프롬프트, 답, 생각, 도구 호출의 인자와 결과, 이미지. 오류도 오류 종류와 필드 이름만 기록합니다.
  • 구글 계정의 이름, 이메일, 프로필, id_token, 회원 식별번호 원문.
  • 발급한 키의 원문.
  • 엣지의 접근 기록.
  • 분석 도구, 광고, 추적 쿠키. 이 사이트는 다른 출처에서 아무것도 불러오지 않습니다.

캐시

  • 캐시는 사용자(키 또는 IP)마다 따로입니다. (사용자, 토큰)의 HMAC으로 찾으므로 다른 사용자의 캐시 유무에 따라 응답 시간이 달라지지 않습니다.
  • 이어지는 대화의 앞부분은 GPU 메모리나 고정 RAM에 두고 마지막 사용 후 15분이 지나면 지웁니다. 고정 RAM은 페이지 파일로 밀려나지 않습니다.
  • 1시간 디스크 캐시는 "ttl": "1h"를 요청했을 때만 씁니다. 키·값 텐서만 AES-GCM으로 암호화해 쓰고, 파일 이름은 HMAC-SHA256입니다. 두 키는 서버 프로세스의 메모리에만 있어 서버를 다시 시작하면 옛 파일은 읽을 수 없습니다. 서버는 시작할 때와 종료할 때 이 파일을 지웁니다.
  • RAM과 디스크 용량은 모든 사용자가 나눠 씁니다. 다른 사용자가 많이 쓰면 내 캐시가 먼저 지워질 수 있습니다.

키와 구글 확인

  • 구글 확인은 OpenID Connect(인증 코드와 PKCE)이며 범위는 openid 하나입니다. 서버는 id_token을 검증한 뒤 회원 식별번호의 HMAC만 남깁니다. 처음 발급할 때 한 번만 거칩니다.
  • 발급한 키는 한 번만 보여 주고 SHA-256 해시로만 저장합니다.
  • 패스키는 공개키와 자격증명 ID만 저장합니다. 비밀키는 이용자의 기기에만 있습니다.
  • 쿠키는 둘이며 모두 HttpOnly, Secure, SameSite=Lax입니다. sclmd_flow는 구글 확인을 시작한 브라우저를 확인합니다(경로 /keys/callback/google, 10분). sclmd_keys는 키 페이지의 세션입니다(경로 /keys, 15분).
  • 키 페이지의 요청은 Origin과 전용 머리글로 이 사이트에서 왔는지 확인합니다.
  • 키를 회수하면 키, 패스키, 구글 계정의 HMAC을 지웁니다.

확인한 방법

  • 요청 53개의 모든 자리(메시지, 도구, 머리글, 잘못된 값, 너무 큰 본문, 끊긴 스트림, 서버 오류 등)에 고유한 표식 문자열을 넣고, 서버가 쓴 모든 파일과 /metrics에서 찾았습니다. 0건이었습니다(실제 모델, 공개 설정, 2026-11-15). 도메인을 거친 요청도 서버와 엣지의 기록에서 0건이었습니다.
  • 한 사용자가 캐시한 10,482토큰 프롬프트를 다른 IP 사용자, 키 사용자, 운영자 PC가 보냈을 때 캐시에서 읽은 토큰은 모두 0이었습니다. 1시간 디스크 캐시도 같았습니다.
  • 서버를 강제 종료한 뒤 남은 디스크 캐시 파일에서 프롬프트의 글과 토큰 번호를 1,289가지 방식으로 찾았고 0건이었습니다. 다시 시작하자 파일은 지워졌습니다.

보장하지 않는 것

  • 요청과 답은 처리하는 동안 RAM과 GPU 메모리에 있습니다. 이어 갈 대화의 토큰 번호 목록은 마지막 사용 후 15분까지 페이지 파일로 갈 수 있는 일반 RAM에 있습니다. 서버가 비정상 종료될 때 Windows가 남기는 덤프에 메모리 내용이 들어가는지는 확인하지 않았습니다.
  • 집 안 LAN 구간은 암호화하지 않습니다.
  • 서버와 엣지는 운영자 개인의 것이고 운영자는 코드를 바꿀 수 있습니다. 외부 감사나 인증은 없습니다. 남에게 보이면 안 되는 내용은 보내지 마세요.
