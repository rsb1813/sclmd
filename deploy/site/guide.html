주소와 키

API 주소
https://ssalmuck-ai.duckdns.org/v1
모델
gemma-4-31b-it
끝점
POST /v1/chat/completions
GET /v1/models
GET /v1/usage
GET /v1/status
키
Authorization: Bearer <키> 또는 x-api-key: <키>

키 없이 보낸 요청은 IP 주소별로 한도를 셉니다. 등록되지 않은 키는 401입니다. 다른 웹사이트의 브라우저 코드에서 직접 부르는 것(CORS)은 지원하지 않습니다.

아래 예제는 키를 환경 변수 SSALMUCK_API_KEY에서 읽습니다.

curl

curl https://ssalmuck-ai.duckdns.org/v1/chat/completions \
  -H "Authorization: Bearer $SSALMUCK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "gemma-4-31b-it",
       "messages": [{"role": "user", "content": "서울의 겨울을 두 문장으로 설명해 주세요."}],
       "max_tokens": 300}'

키 없이 쓰려면 Authorization 줄을 뺍니다.

Windows의 curl은 명령줄의 한글을 UTF-8로 보내지 않아 400이 날 수 있습니다. 이때는 요청을 UTF-8 파일로 저장해 -d @request.json으로 보냅니다.

파이썬

import os
from openai import OpenAI

client = OpenAI(base_url="https://ssalmuck-ai.duckdns.org/v1",
                api_key=os.environ["SSALMUCK_API_KEY"])

reply = client.chat.completions.create(
    model="gemma-4-31b-it",
    messages=[{"role": "user", "content": "파이썬으로 피보나치 수를 구하는 함수를 써 주세요."}],
    max_tokens=800,
)
print(reply.choices[0].message.content)

키 없이 쓰려면 api_key에 아무 값을 넣고 Authorization 머리글을 빈 값으로 덮어씁니다.

client = OpenAI(base_url="https://ssalmuck-ai.duckdns.org/v1",
                api_key="none",
                default_headers={"Authorization": ""})

자바스크립트

Node.js 18 이상의 fetch:

const res = await fetch("https://ssalmuck-ai.duckdns.org/v1/chat/completions", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": `Bearer ${process.env.SSALMUCK_API_KEY}`,
  },
  body: JSON.stringify({
    model: "gemma-4-31b-it",
    messages: [{ role: "user", content: "자바스크립트의 Promise를 한 문단으로 설명해 주세요." }],
    max_tokens: 400,
  }),
});
if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`);
const data = await res.json();
console.log(data.choices[0].message.content);

openai 패키지는 baseURL만 바꿉니다.

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://ssalmuck-ai.duckdns.org/v1",
  apiKey: process.env.SSALMUCK_API_KEY,
});
const reply = await client.chat.completions.create({
  model: "gemma-4-31b-it",
  messages: [{ role: "user", content: "안녕하세요" }],
});
console.log(reply.choices[0].message.content);

스트림

"stream": true면 OpenAI와 같은 SSE로 응답하고 data: [DONE]으로 끝납니다. 첫 토큰이 나올 때까지 서버는 15초마다 : ping 줄을 보냅니다. 공식 라이브러리는 이 줄을 무시합니다. 직접 읽을 때는 :로 시작하는 줄을 건너뜁니다. 입력이 32,768토큰이면 첫 토큰까지 약 20초 걸립니다.

stream = client.chat.completions.create(
    model="gemma-4-31b-it",
    messages=[{"role": "user", "content": "짧은 시를 한 편 써 주세요."}],
    stream=True,
)
for chunk in stream:
    if chunk.choices and chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)

스트림이 아닌 요청은 답이 끝날 때까지 아무것도 오지 않습니다. 클라이언트의 시간 제한을 넉넉히 둡니다.

생각

기본은 생각 없이 답합니다. "reasoning_effort"에 none, minimal이 아닌 값을 주거나 "thinking": {"type": "enabled"}를 주면 생각한 뒤 답합니다. 생각은 reasoning_content로 오고, 스트림에서는 delta.reasoning_content로 옵니다. 생각 토큰도 출력 토큰으로 셉니다.

등급과 한도

공개한 기본값입니다.

등급대상시간당하루
키발급받은 키125만 토큰4,000만 토큰
검증 IP한국 가정용·모바일 회선에서 요청이 과하지 않은 IP75만 토큰1,500만 토큰
미검증 IP해외, 데이터센터·호스팅 대역, 조건을 어긴 IP30만 토큰750만 토큰
  • 사용자는 키로 구분하고, 키가 없으면 IP 주소로 구분합니다. IPv6는 /64 단위입니다.
  • 요청마다 캐시되지 않은 입력 + 출력 × 5 + 캐시된 입력 × 0.1을 차감합니다. 모든 등급이 같습니다. 입력 2,000토큰에 출력 500토큰이면 4,500입니다.
  • 지난 60분과 지난 24시간을 1분 단위로 셉니다.
  • 시간당 한도를 넘은 요청도 받지만 처리 순서가 크게 밀립니다.
  • 하루 한도를 넘으면 429와 Retry-After를 돌려줍니다. 키 없는 요청 전체에도 하루 한도가 있습니다.
  • 처리 순서는 키, 검증 IP, 미검증 IP 순입니다. 같은 등급에서는 한도 안의 요청이 먼저입니다.
  • 검증 IP의 판정 기준은 공개하지 않습니다. 국가와 대역은 서버 안의 DB-IP Lite(db-ip.com, CC BY 4.0)로 판별합니다.
  • 내 사용량은 GET /v1/usage로 봅니다. 응답마다 시간당 기준의 x-ratelimit-* 머리글이 붙습니다.

동시 요청

한 사용자가 동시에 보낸 요청은 차례로 우선순위가 낮아집니다.

진행 중인 요청우선순위
첫 1개높음
다음 3개보통
다음 8개낮음
13번째부터429 concurrency_limit

오류와 재시도

  • 하루 한도: 429, rate_limit_exceeded. Retry-After(초)와 retry-after-ms가 붙습니다. 몇 시간일 수 있습니다.
  • 동시 요청: 429, concurrency_limit. 진행 중인 요청이 끝나면 다시 받습니다.
  • 서버 재시작 중: 503과 Retry-After. 서버가 꺼져 있으면 502.
  • 파이썬 openai 라이브러리는 Retry-After가 120초 이하면 두 번까지 다시 시도하고, 그보다 길면 바로 RateLimitError를 냅니다.
import time
from openai import RateLimitError, APIStatusError

def ask(messages, tries=5):
    for _ in range(tries):
        try:
            return client.chat.completions.create(model="gemma-4-31b-it", messages=messages)
        except (RateLimitError, APIStatusError) as e:
            if e.status_code not in (429, 502, 503):
                raise
            wait = float(e.response.headers.get("retry-after", "5"))
            if wait > 600:      # 하루 한도
                raise
            time.sleep(wait)
    raise RuntimeError("재시도 실패")

프롬프트 캐시

캐시는 사용자마다 따로이며 다른 사용자와 공유하지 않습니다. 캐시된 입력은 0.1배로 셉니다.

  • 대화를 이어 가면 앞의 같은 부분은 다시 읽지 않습니다. 마지막 사용 후 15분 동안 유지합니다.
  • content part나 메시지에 "cache_control": {"type": "ephemeral"}를 붙이면 그 지점까지 저장합니다. "ttl"은 "15m"(기본, RAM) 또는 "1h"(RAM과 암호화된 디스크)입니다.
  • 표시는 요청당 4개까지입니다. 1,024토큰보다 짧은 앞부분은 저장하지 않고 x-sclmd-ignored 머리글에 적습니다.
  • usage.prompt_tokens_details.cached_tokens는 캐시에서 읽은 토큰, cache_write_tokens는 새로 저장한 토큰입니다.
  • 31,000토큰 문서에서 첫 토큰까지 캐시 없이 22초, RAM 캐시 0.2초, 디스크 캐시 0.6초였습니다.
reply = client.chat.completions.create(
    model="gemma-4-31b-it",
    messages=[
        {"role": "system", "content": [
            {"type": "text", "text": long_document,          # 1,024토큰 이상
             "cache_control": {"type": "ephemeral", "ttl": "1h"}},
        ]},
        {"role": "user", "content": "이 문서의 요점을 세 줄로 정리해 주세요."},
    ],
)
print(reply.usage.prompt_tokens_details)

문맥 길이

  • 입력은 32,768토큰까지입니다. 넘으면 400, context_length_exceeded입니다.
  • 출력은 8,192토큰까지입니다. max_tokens나 max_completion_tokens가 더 크면 8,192로 줄이고 x-sclmd-ignored: max_tokens로 알립니다.
  • 요청 본문은 32MiB까지이며, 넘으면 413입니다.

지원하지 않는 필드

  • 지원하지 않는 필드는 무시하고 그 이름을 x-sclmd-ignored 머리글에 적습니다.
  • n이 1이 아닌 값, logprobs, strict json_schema는 400입니다.
  • 도구 호출은 tools, tool_choice의 auto·none, tool 메시지를 지원합니다. required나 특정 함수 지정은 강제하지 않고 머리글에 적습니다.
