# sclmd

Gemma 4 31B (dense) on a single RTX 5080 16 GB: as close to the original as the VRAM allows, as fast as the memory bandwidth allows.
Every weight sits in VRAM as 3- or 4-bit pair codes and is multiplied straight from the codes on the tensor cores; a small drafter guesses seven tokens ahead and the main model verifies them in one pass, which leaves the text unchanged.

- `chat.bat`: the terminal chat (`/?` lists its commands). It picks how many matrices get 4 bits from the VRAM that is free when it starts.
- `serve.bat`: an OpenAI-compatible server for several users at once (`http://127.0.0.1:8001/v1`; `-h` lists its options): every pass of the model carries tokens of all requests under way, 137 tok/s for one reply and 546 together for eight, and a prompt is read at about 1,000 tokens a second (980 at 6,000 tokens); `--keyless` halves what a long conversation's token takes (21 KB), for one conversation of 81,920 tokens or two of 40,960 (`--context`) (3 bits a weight; `--kv-gib 0.68` gives the chat's 3.48 bits and room for fewer conversations); `--prefix-gib 2` keeps a shared system prompt's state in RAM and copies it to the next request that begins with it (lossless: 60 requests with a 1,018-token system prompt in 31.5 s instead of 93); `--int8` multiplies on the integer tensor cores (lossy option, no loss measured on translation into Korean: prompts read at 1,268 / 1,237 / 1,189 tok/s at 512 / 2,048 / 6,000 tokens, 825 tok/s for sixteen replies together); `--kv4` keeps the keys and values of 49 sliding layers at 4 bits (lossy option, no loss measured on translation into Korean, KL +0.009): the default pool holds 37 / 15 / 8 / 7 / 2 conversations of 200 / 500 / 1,000 / 2,000 / 8,000 tokens instead of 23 / 9 / 4 / 4 / 1, and sixteen clients' second turns run at 605 tok/s instead of 307, while a single conversation is 3.5% slower; `--int8 --wide-rows 256` (or 128) reads several requests' prompts in one pass of up to that many rows (the same replies, with `--kv4` too: a 2,048-token prompt at 2,376 tok/s instead of 1,236; with `--int8 --kv4`, 16 clients with 500-token prompts get their first token after 2.9 s instead of 5.9 and 1.8 times the requests a second, at 2,000 tokens 1.8 times; it takes 0.08 GiB of the keys and values' room, and a conversation of more than 1,056 tokens 89 MB more, 46 MB with `--kv4`). A conversation whose reply a stop string ended is kept for its next turn like any other. Request fields it does not serve are named in the `x-sclmd-ignored` response header, except n other than 1, logprobs and a strict json_schema, which get a 400 (`--lenient-fields` refuses nothing, `--strict-fields` everything it would ignore). Off by default, since each refuses something that was served before: `--max-body-mb 32` caps a body (413), `--idle-timeout 120` closes idle connections, `--max-connections 256` answers 503 past that many, `--look-gone 1` stops writing a reply that is not streamed once its client has left (a client that closes its sending side after the request then gets no answer) (`scripts/serve_contract.py`). Tool calls in Gemma 4's own format (`sclmd/tools.py`): `tools`, `tool_choice` auto or none, role `tool` messages and assistant `tool_calls`; the reply's calls are read on token ids and come back as `message.tool_calls` (a stream sends each call when it closes), and an agent's next step reuses the kept conversation, so that it reads only the new tool result. A tool or call it cannot declare or write is left out and named in `x-sclmd-ignored` (`--strict-fields`: 400); `tool_choice` required or a named function is not enforced (no grammar) and is named. Operating it (`scripts/serve_admin.py`, the same reply tokens either way): `GET /metrics` (Prometheus text), and, off until asked for, API keys from `SCLMD_API_KEY` or `--api-key-file` (`--host 0.0.0.0` without one starts with a loud warning, `--require-key` refuses), `--max-waiting N` (429 with Retry-After) and `--queue-timeout S` (503), `--request-log` and `--status-file`, and `serve.toml` with any option (`serve.example.toml`); `python -m scripts.soak` runs mixed traffic with faults on a timer against it and checks its books. Also off by default (`scripts/serve_ops.py`, design.md 6.15): `--image auto` starts in about 6 s instead of 13 by reading the engine's packed codes from an image under `data/images` (the same bytes; written once per plan and build, 11.7 GB for 3 bits everywhere), and `serve.bat --supervise` starts the server again when its engine dies or hangs (it then runs with `--crash-only`: exit 75) and answers 503 with Retry-After on its port meanwhile (`logs\supervise.log`; while `logs\serve_sleep` exists the server is stopped and its VRAM free).
- `design.md`: the model, the budget, and what was measured (Korean)
- `checklist.md`: what is done and what is being done now (Korean)

From scratch, in this order (Python runs from the parent project's environment, `..\.venv`; weights are never committed):

| Step | Command | Takes |
|---|---|---|
| Checkpoints into `C:\models` (`SCLMD_MODELS` to change) | `python -m scripts.download orig drafter` (without names: Google's QAT checkpoints too, which nothing here needs any more) | 64 GB (126 GB) |
| The token sets | `python -m scripts.build_sets` | |
| The original's outputs over the evaluation set (the reference) | `python -m scripts.reference`, and again with `--quant fp32` | 2 min each |
| Pair codes for every layer, at 3 and 4 bits | `python -m scripts.quantize` | 23 min, 28 GB |
| The output head's and the drafter's codes | `python -m scripts.quantize_head`, `python -m scripts.quantize_drafter` | 3 min each |
| The engine | `engine\build.bat` (CUDA toolkit and MSVC) | |
| What each matrix is worth at 4 bits, on text the model writes itself (the reports are already in `data/`): a plan to write with, the text, the original over it, the measurements | `python -m scripts.plans`, `sh scripts/sweep.sh`, `python -m scripts.allocate --gib 11.1`, `python -m scripts.own_text`, `python -m scripts.reference --set own_v1` (and again with `--quant fp32`), `sh scripts/sweep_own.sh` | 50 + 25 min |
| Chat | `chat.bat` | 15 s to load |

Checks: `python -m pytest` (small random models, a GPU for the engine's tests; the server's HTTP side without a model), `python -m scripts.serve_canned 8017` with `uv run --no-project --with openai python scripts/openai_client_check.py 8017` (the official openai client against the server's protocol, a canned reply in the engine's place; a second canned server started with `--max-body-mb 1 --max-connections 1`, given as a second port, adds the 413 and 503 items), `python -m scripts.tool_prefix_check` (no GPU: an agent loop's kept conversation is a prefix of its next step, and calls written by the template read back), `python -m scripts.tool_call_bench --think off` then `--score` (50 BFCL-style tool-call items, 16 in Korean), `python scripts/tool_loop_bench.py --clients 1,4 --check` (agent loops against a running server), `python -m scripts.engine_check` (the real model on the engine against the same codes in PyTorch and against the original), `python -m scripts.say "..." --check` (text with the drafter equals text without), `python -m scripts.long_recall` (facts from the start and middle of a 7,000-token prompt), `python -m scripts.batch_bench` (several texts at once, each the text it is alone), `python scripts/serve_bench.py` (clients against a running server), `python -m scripts.speed_check --against base` (fixed prompts and seeds: the same tokens as before a change, and how fast; `--chat` through the chat's own loop), `python -m scripts.bits_check --against base` (two builds of the engine give the same bits: `SCLMD_DLL` picks the build), `python -m scripts.prefill_check` (how fast a prompt is read, and that what it leaves is the same bits; `python scripts/serve_bench.py --long 1500,6000` for the same through a running server).

Benchmarks: `python -I scripts/bench_prepare.py --out data/bench` (the questions as local prompt files), `python -m scripts.bench --task mmlu_pro --limit 140` (the replies; `sh scripts/bench_queue.sh <this folder>` runs `data/bench/queue.txt` and can be paused with `logs/pause`), `python -I scripts/bench_score.py` (scores, `data/bench_summary.json`), `python -m scripts.bench_paired --side ours | orig | score` (the original and the engine on the same MMLU-Pro questions, the answer's letter without thinking: 71.3% and 70.0% on 2,800).
